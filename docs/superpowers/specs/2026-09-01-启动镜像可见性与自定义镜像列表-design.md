# 启动镜像可见性与自定义镜像列表 — 设计

> 2026-09-01 · 触发：真机反馈「个个都写着设为启动镜像，但当前启动镜像是哪个，没有地方说明和编辑」
> 本文只写「做什么、为什么这么做」，实施顺序见文末分批。

## 1. 问题

「当前启动镜像」是 `default_config.docker.image`（全局，`z.string().min(1)`），模型可用
`overrides.docker.image` 单独覆盖。官方镜像卡与自定义镜像卡的「设为启动镜像」按钮写的是**同一个键**。

它今天**有**显示：`ref === currentImage` 的那一行把按钮换成「当前生效」徽标。但这个显示有三处不足，
其中第二条是真缺陷：

| # | 问题 | 性质 |
|---|---|---|
| 1 | 要知道当前是哪个，得在两张表里扫徽标，没有一处权威读数 | 可用性 |
| 2 | **徽标可能一行都不出现**，当前值因此完全不可见 | 缺陷，见 §1.1 |
| 3 | 只能从「已拉取」里挑，无法直接填一个 ref | 能力缺失 |

反馈的直接诱因是第四件事：自定义镜像卡右列宽 420px，而表格四列固定宽合计约 1160px，
「操作」列被挤到横向滚动区外，用户连徽标都看不见——所以观感是「个个都写着设为启动镜像」。

### 1.1 徽标可能一个都不出现

两张列表的取值口径不同：

- **官方镜像表**：`SERVER_VARIANTS` 是**固定的 8 个 tag**，不管本地拉没拉都在表里。当前值只要是这 8 个之一，
  必定有一行标「当前生效」。
- **自定义镜像列表**：只列 `localImages` 里**本地已拉取**、且不在官方 8 个里的 tag。

因此只要当前值 **既不在官方 8 个 variant 里、本地又没有**，两张表就没有任何一行匹配，
这个值在界面上彻底消失。触发路径是现实的：在面板外 `docker rmi` 掉、从别的机器导入配置、
或直接改 `panel.db`。而这恰恰是最需要看见它的时候——下一次启动模型必定失败。

（面板自身的删除接口挡了这条路：`DELETE /api/v1/images` 对当前生效镜像返回 400 `current_image`。
但它挡不住面板外的 docker 操作。）

## 2. 已定决策

| 决策 | 结论 | 依据 |
|---|---|---|
| 读数与编辑入口的层级 | **提到镜像管理区块顶部**，独立一张卡，排在官方镜像卡之上 | 它是全局值，两张表都在往它写；放进任一张表所属的卡都会错位（选中官方镜像时读数出现在「自定义」卡里，反之亦然） |
| 输入校验强度 | **接受任意 ref，不做「必须本地已存在」的阻断校验** | 运行时 `createWithAutoPull` 已在 404 时先 `pull` 再重试建容器；与自定义镜像卡既有的规格决策 6「配错自负，不作推荐用法」一致；且不必为此新开校验接口 |
| 卡片化范围 | **只改自定义镜像列表**，官方镜像表保持表格 | 官方卡是全宽的，表格展开正常；八个 variant 要横向对比平台与状态，表格的可扫性强于卡片，且卡片占高翻倍。被挤坏的只有 420px 那张 |
| 写入路径 | 输入框保存与列表按钮**共用同一个写入函数** | 两处写的是同一个键，分开实现必然漂移 |

## 3. 架构与落点

镜像管理区块现有结构：`image-card.tsx` 持有全部状态 + `official-images-card.tsx` /
`custom-image-card.tsx` 两张纯渲染卡。

新增**第三张纯渲染卡** `current-image-card.tsx`，状态仍由 `image-card.tsx` 持有，
经 props 下发——与既有两张卡同构，不新开状态源。

可测判定下沉 `src/lib/current-image.ts`（配 `.test.ts`）：

```ts
/** 在本地镜像里按 ref 精确匹配 tag，命中时返回体积，供读数卡的状态行用 */
export function findLocalImage(
  ref: string,
  localImages: readonly { tags: string[]; size: number }[],
): { sizeBytes: number } | null;

/** 保存按钮可用性：去空白后非空，且与已保存值不同 */
export function isCurrentImageSavable(draft: string, saved: string): boolean;
```

组件本身不做单测：vitest 是 `environment: "node"` 且未装 jsdom，组件渲染测不了，
可测判定一律下沉到 `src/lib/*.ts`（项目既有约定）。

## 4. 「当前启动镜像」卡

```
┌──────────────────────────────────────────────────────────┐
│ ⬢ 当前启动镜像                                            │
│   新建与启动模型时默认使用；单个模型可在编辑页的           │
│   「镜像」字段单独覆盖                                     │
│                                                           │
│   [ghcr.io/ggml-org/llama.cpp:server-cuda        ] 〔保存〕│
│   ✓ 本地已拉取 · 5.6 GB                                    │
└──────────────────────────────────────────────────────────┘
```

**状态行三态**（由 `findLocalImage` 与草稿是否为空共同决定）：

| 条件 | 呈现 | 是否阻断保存 |
|---|---|---|
| 本地已拉取 | `✓ 本地已拉取 · <体积>` | 否 |
| 本地没有 | `⚠ 本地未拉取 · 首次启动时自动拉取` | **否**（见 §2 决策二） |
| 去空白后为空 | `镜像名不能为空` | **是**，保存按钮禁用 |

**保存行为**：`PUT /api/v1/settings/default_config`，整份 `DefaultConfig` 回写
（与现有 `setAsDefaultImage` 完全同一条路径）。成功后 toast、重新拉取镜像清单、
并复用既有的 `checkRestartHint()`——有模型在跑时提示需重启才生效。

**说明文案是 A 级、常驻不收进悬停**：「模型可在编辑页单独覆盖」这一条不说，
用户会困惑于「我明明改了启动镜像，为什么这个模型还是用旧的」。

### 4.1 草稿与已保存值的同步（两处易写错）

**其一：列表按钮改值后，输入框必须跟着走。** 「设为启动镜像」和输入框写的是同一个键，
但输入框有自己的草稿 state。点了列表按钮之后草稿若不同步，输入框会停在旧值上，
下一次点「保存」就把刚设好的值又改回去了。约定：`writeImage(ref)` 成功后**统一**把草稿
重置为新值，无论调用方是列表按钮还是输入框自己。

**其二：首屏不等 `catalog` 就能显示读数。** 已保存值有两个来源——服务端渲染时经
`initialImage` prop 直接传下来的，和 `GET /api/v1/images` 响应里的 `currentImage`。
输入框的初值取 `initialImage`（首屏即有，不闪空），状态行则要等 `catalog` 到位才能判本地存在性，
在此之前不渲染状态行（不是渲染成「未拉取」——那会在加载的一瞬间报一个假警告）。

## 5. 自定义镜像列表改卡片

`<Table>` 换成 `ul` / `li` 卡片列表，每张卡：

```
┌─────────────────────┐
│ quantatrisk/funasr…  │  ← 等宽字体，长名换行不截断
│ 1.2 GB · 08-21 14:30 │
│ 〔设为启动镜像〕〔删除〕│
└─────────────────────┘
```

当前生效的那张把「设为启动镜像」换成「当前生效」徽标（与改造前同一判定 `row.tag === currentImage`）。
按钮的 disabled 逻辑、行内错误提示、删除守卫的 title 提示全部原样保留，只换容器形态。

420px 的四列截断问题随之消失——卡片是纵向堆叠，不存在固定列宽。

## 6. 明确划出去的

- **不做**「N 个模型单独覆盖了镜像」的统计：要遍历全部模型记录，收益不抵成本
- **不做** ref 的格式校验（registry / 仓库名 / tag 正则）：`min(1)` 之外交给 docker 报错，
  与决策二同源
- **不动**官方镜像表的形态，**不动**拉取、删除的既有守卫与错误透出

## 7. 分批

1. **判定层**：`src/lib/current-image.ts` + `.test.ts`（先测后写）
2. **写入路径重构**：`image-card.tsx` 里把 `setAsDefaultImage` 的写入核心抽成 `writeImage(ref)`，
   列表按钮包 `busyRef`、输入框包自己的 saving 标志。此批不改任何 UI，行为应完全不变
3. **读数卡**：新增 `current-image-card.tsx` + 接线 + i18n（zh/en 对称）
4. **列表卡片化**：`custom-image-card.tsx` 的 `<Table>` 换 `ul/li`

每批跑 `npx tsc --noEmit` / `pnpm run lint` / `pnpm test` / `pnpm run build`，
第 3、4 批另需真机截图确认。
