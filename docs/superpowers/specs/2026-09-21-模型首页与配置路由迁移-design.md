# 模型首页与配置路由迁移

> 2026-09-21 · 状态：设计定稿，待实现

## 1. 背景与目标

模型区当前只有两页：`/models`（配置列表）与 `/models/repos`（仓库档案）。用户进入模型区时最想先看到的两件事——**哪些模型在跑**、**手上有哪些仓库**——分散在概览页 `/` 的一张右列小卡和另一个二级页里，都不是模型区的落脚点。

本期把 `/models` 腾出来做模型区首页，配置列表迁到 `/models/profiles`。首页本期只放「正在运行」与「最近更新的仓库」两块，后续还会继续长（见 §7）。

## 2. 路由结构

| 路径 | 内容 | 变化 |
|---|---|---|
| `/models` | 模型首页：正在运行 + 最近更新的仓库 | **新建** |
| `/models/profiles` | 模型配置列表（含命名空间二级栏分组） | **由 `/models` 迁入** |
| `/models/repos` | 仓库档案列表 | 不变 |
| `/models/new`、`/models/[name]/edit`、`/models/[name]/duplicate` | 新建/编辑/复制配置 | 不变 |

配置页的子路由（新建/编辑/复制）**不跟着迁到 `/models/profiles/` 下**：它们与配置列表是"列表 → 表单"的关系而不是层级归属，迁移会波及一批与本期目标无关的路径，YAGNI。

### 2.1 二级栏

三组 tab，首页第一格：

```
MODELS
模型                    [↓ 新建下载]
──────────────────────────────
━ 01  首页          ◀ 选中
      运行中与仓库
— 02  HuggingFace
      仓库下载与文件状态
— 03  配置
      模型配置列表
```

命名空间分组（全部模型 / main / …）**只在 `/models/profiles` 出现**——它本来就是配置列表的筛选器，首页与档案页都不按命名空间切片。「＋新建命名空间」按钮随之只在配置页可见。

`lib/models-tabs.ts` 的 `ModelsTab` 扩成 `"home" | "repos" | "configs"`，`MODELS_TABS` 扩成三条。`resolveModelsTab` 按这个顺序判定，**只有恰好等于 `/models` 才是 home**：

1. `/models/repos` 或 `/models/repos/…` → `repos`
2. 其余所有 `/models/…` 子路径（`/models/profiles`、`/models/new`、`/models/<name>/edit`、`/models/<name>/duplicate`）→ `configs`
3. 恰好 `/models` → `home`

第 2 条是刻意的兜底方向：编辑/新建一个配置时，二级栏该高亮「配置」而不是「首页」。旧判定里这些子路由本就落 configs，这里保持不变，只是把「默认落 configs」从"其余全部"收窄为"其余子路径"，把 `/models` 自身让给 home。`/models/repos-other` 这类前缀不是目录边界的路径仍落 configs（既有用例已覆盖，行为不变）。

### 2.2 跳转点迁移

9 处指向 `/models` 的跳转按语义分两类，不能一刀切：

**改指 `/models/profiles`**（语义是「回到 / 去往配置列表」）：

| 位置 | 场景 |
|---|---|
| `models/[name]/edit/edit-form.tsx:204` | 保存后返回 |
| `models/[name]/edit/edit-form.tsx:274` | 取消 |
| `models/new/wizard.tsx:247` | 向导完成 |
| `models/new/wizard.tsx:382` | 向导取消 |
| `models/[name]/duplicate/duplicate-form.tsx:190` | 取消 |
| `(panel)/page.tsx:238` | 概览页空态按钮（空态时首页无内容可看，要启动模型得先有配置） |
| `chat/page.tsx:136` | 「没有运行中的模型，去启动一个」 |
| `api/v1/proxy/llama/[[...path]]/route.ts:135,140` | 503 响应体的 `hint` |
| `lib/onboarding.ts:35` | 新手引导「启动第一个模型」步骤 |

**保持 `/models`**：`components/shell/sidebar.tsx:70` 一级侧栏「模型」入口——它是模型区的入口，应落到首页。侧栏选中态按 `startsWith("/models")` 判定，三个页面都覆盖，无需改动。

非路由的 `/models` 字面量（容器内挂载点 `model_mount`、`runtime.ts`、`doctor.test.ts`、`proxy-rewrite.test.ts` 等）**一律不动**，迁移时必须逐个甄别，不能全局替换。

## 3. 模型首页

### 3.1 页头

`PageHeader`，统计位给三个读数：运行中数量（tone: hot）、配置数量、仓库数量。

### 3.2 「正在运行」区

每个运行中模型一张卡，**横向平铺一行**（运行中模型通常 1–3 个，铺一行信息给得最足）。卡片内容即概览页现有运行卡的完整形态：

- 显示名 + 模型 id + 默认模型徽标
- 容器名
- 端口（含复制 curl 按钮与端点动作）
- 启动时间
- 停止 / 重启 / 设为默认（`RuntimeCardActions`）

空态：没有运行中的模型时显示一行说明 + 「去配置列表启动」按钮（指 `/models/profiles`）。

### 3.3 「最近更新的仓库」区

复用 `/models/repos` 的仓库卡片，按「最近更新」倒序取前 5 个，区标题右侧挂「查看全部 →」跳 `/models/repos`。

**「最近更新」口径**：该档案目录（含子目录）下所有文件的**最大 mtime**。文件落盘那一刻就是它，所以下载完成、手动 rsync 拷入、外部工具写入都算数，比只查 `download_history` 更准。目录为空或目录已不存在时回退到档案的 `created_at`。

实现上零额外开销：`scanTree` 返回的每个文件已带 `mtime`，`decorateProfileStats` 本就在遍历每个档案的全部文件，循环里多维护一个 max 即可，不需要第二次扫盘。

空态：复用档案页现有的空态文案（`pages.repos.emptyTitle` / `emptyDescription`）。

## 4. 概览页运行卡精简

概览页 `/` 右列那张运行状态卡回归「全局健康一瞥」的职责，细节与操作交给模型首页。

**有运行中模型时**——保留：运行中徽标（含数量）、每个模型一行（显示名 + 端口）。移除：容器名、启动时间、复制 curl 与端点动作、停止/重启/设为默认。卡片底部新增「查看详情 →」跳 `/models`。

**无运行中模型时**——整块改为占满卡片宽度的**虚线边框空状态面板**，按现有的两态区分文案，两态的行动按钮都指向 `/models/profiles`：

| 前提 | 文案方向 |
|---|---|
| 有模型配置但都没在跑 | 「当前没有运行中的模型」+ 去配置列表挑一个启动 |
| 一个模型配置都没有 | 「还没有模型配置」+ 去创建第一个配置 |

两态复用同一个虚线面板组件，只换文案与按钮文字。

## 5. 组件边界

- `RepoCard` 从 `models/repos/repos-view.tsx` 抽成共享组件，首页与档案页共用。
- 运行卡**不做共享**：概览页精简后与首页的形态已经不同（一个是两行摘要，一个是带操作的完整卡），强行共享会退化成一堆开关参数。首页那套独立实现，概览页保留自己的精简版。
- 排序与取前 5 的判定下沉到 `src/lib`（纯函数，node 环境可测），页面只负责渲染。

## 7. 本期不做

- **HF 最新排行榜拉取**、**模型搜索**：用户明确延后，首页会为它们继续长，但不在本期。
- 首页按命名空间切片。
- 配置子路由迁到 `/models/profiles/` 下（见 §2）。
- `/models` 旧链接的兼容重定向：`/models` 本身仍然有效（变成首页），不存在失效链接，无需重定向。
