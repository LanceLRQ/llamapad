# 排错

## 登录报 500，或日志里有 `SQLITE_CANTOPEN`

**现象**：浏览器打开面板后登录请求直接 500，容器日志能看到 `SQLITE_CANTOPEN`。

**原因**：面板容器以 `.env` 里 `PUID`/`PGID` 指定的身份运行，如果这个身份对宿主机的 `data/` 目录没有写权限，SQLite 连自己的数据库文件都打不开。这在模型库是 `root` 属主、而 `.env` 又没同步设置 `PUID=0`/`PGID=0` 时最常见。

**怎么办**：用 `stat -c '%u:%g' data/` 确认 `data/` 目录的实际属主，让 `.env` 里的 `PUID`/`PGID` 与之对齐，或反过来 `chown` 对齐 `.env`（`data/` 是面板自己的数据卷，改属主没有副作用）。完整的权限配置方法见[部署与运维](./deployment.md)。

## 下载失败 `EACCES: permission denied, mkdir`

**现象**：新建下载任务后很快失败，错误信息里带 `mkdir` 和 `EACCES`。

**原因**：与上一条同源——面板运行身份对宿主机的 `models/` 目录没有写权限，下载器建不了目标子目录。模型库常见是 `root` 手工建的目录，而面板默认非 root（`node`，uid 1000）运行。

**怎么办**：同样用 `stat -c '%u:%g' models/` 确认属主，调整 `.env` 的 `PUID`/`PGID` 对齐它——不要反过来给模型库整个 `chown`，那可能是上百 GB 的目录，代价远大于改一个环境变量。详见[部署与运维](./deployment.md)的「运行身份与目录权限」一节。

## 中转接口报 502「容器端口未就绪」

**现象**：调用 `/api/v1/proxy/llama/*`（或 Playground 发消息）时收到 502，`{"error":"容器端口未就绪"}`。

**原因**：模型容器已经启动，但 llama-server 进程还没开始监听端口——大模型冷启动（加载权重、分配显存）可能需要几十秒，面板判定"容器在跑"和 llama-server 真正能接受请求之间存在窗口期。

**怎么办**：等几秒重试。这是正常的启动过程；如果长时间（超过一两分钟）持续 502，去[日志页](./monitoring.md)的容器日志确认 llama-server 是否卡在加载、或是配置了超出显存的参数导致启动失败。

## 中转接口报 503「没有运行中的模型」

**现象**：调用中转接口收到 503，`{"error":"没有运行中的模型","hint":"/models"}`。

**原因**：当前没有任何模型在运行——要么从未启动过，要么已经停止。中转接口只转发给当前正在运行的那一个模型，没有可转发的目标时直接拒绝。

**怎么办**：去模型列表启动目标模型。

## HTTP 局域网访问下，某个按钮没反应或整页报错

**现象**：面板经局域网 IP + HTTP 访问（未套 HTTPS）时，「复制」按钮点了没反应，或者某个新建操作（如 Webhook「添加渠道」）直接让整页变成一片报错。

**原因**：`navigator.clipboard`（剪贴板 API）与 `crypto.randomUUID`（生成随机 ID）都只在「安全上下文」（HTTPS 或 `localhost`）暴露，纯局域网 HTTP 访问下它们要么是 `undefined`、要么调用即抛异常。面板已经给这两处加了兼容回退（复制退化到 `execCommand`，随机 ID 退化到 `getRandomValues`），大多数场景不会再遇到；如果用的是较旧的镜像版本，仍可能碰到。

**怎么办**：升级到较新版本的面板镜像；如果需要彻底解决安全上下文的限制（比如让浏览器地址栏显示锁标、避免类似问题反复出现），套一层 HTTPS 反代，见[HTTPS 反代](./nginx.md)。

## llama.cpp 自带 web UI 聊天报 400

**现象**：点页头「打开 llama UI」进入 llama.cpp 自带的 web UI 后，发消息返回 400。

**原因**：`dry_penalty_last_n` 参数在该 web UI 的本地设置里被存成了 `-1`，而较新版本的 llama-server 校验要求这个值 `≥0`。这个设置存在 llama-server 那个 origin（`:18080` 等）的 `localStorage` 里，面板与它不同源，改不到。详见[推理接口](./inference.md)的已知边界。

**怎么办**：在 llama.cpp 自带 web UI 自己的设置面板里，把这个参数改成 `0` 或更大的值。这是 llama.cpp 上游的行为，不是面板的问题。

## 构建镜像卡在 `apt-get`

**现象**：`docker build` 长时间停在安装系统依赖包的步骤，几分钟都下不完一个几 MB 的包。

**原因**：外网受限的环境下直连 Debian 源太慢。构建代理参数不是可选的性能优化——Dockerfile 把代理写进了 `ENV`，这个值会进 Docker 的构建缓存键，漏传一次代理，`apt-get` 与依赖安装两层缓存就会全部失效重跑。

**怎么办**：用 `--build-arg HTTP_PROXY=...` 等参数带上代理地址（宿主机局域网 IP，不能是 `127.0.0.1`——构建容器里的 `127.0.0.1` 指向它自己）。完整命令与验证方法见[部署与运维](./deployment.md)的「构建代理」一节。

## GPU 指标不显示

**现象**：概览页的显存、GPU 利用率两张卡不出现，或者出现一条「GPU 监控不可用」的提示。

**原因**：面板容器需要能调用宿主机的 `nvidia-smi` 才能采集这两项指标，这依赖 `docker-compose.yml` 里的 `gpus: all` 配置。缺了这一行，面板容器内根本看不到 GPU 设备。

**怎么办**：确认 `docker-compose.yml` 有 `gpus: all`，并且宿主机装好了 NVIDIA Container Runtime，然后 `docker compose up -d` 重建容器（不是 `restart`，这类容器级配置需要重建才会生效）。纯 CPU 部署这是正常状态，不需要处理。

## 网络吞吐 / 磁盘 IO 指标缺失

**现象**：概览页的「网络收发」或「磁盘 IO」卡长期空白。

**原因**：这两组指标都需要把宿主机的 `/proc` 挂载进容器，对应 `docker-compose.yml` 里的 `/proc:/host/proc:ro`。没挂这一行，两组指标都会静默缺省，不影响其余指标。

**怎么办**：确认 compose 文件里有这一行挂载，然后 `docker compose up -d` 重建容器（挂载是容器级配置，`restart` 不会应用）。详见[监控与日志](./monitoring.md)。

## 启动模型报 409

**现象**：点「启动」返回 409。

**原因**：上一个启停请求还没结束——面板的启动/停止/重启操作互斥，同一时刻只允许一个在执行。并发的第二个请求会被直接拒绝而不是排队：排队会让人搞不清最终跑起来的是哪一个模型，失败后重试一次成本更低。

**怎么办**：等当前操作完成后重试，通常几秒到几十秒（取决于模型加载耗时）。

## 思考强度传了值没生效，或模型启动被拒绝

**现象**：在模型编辑页给「思考强度」配了一个固定值，保存后模型启动被拒绝（422），或者感觉传了值但推理时没有任何变化。

**原因**：一个模型支不支持 `reasoning_effort`、接受哪些取值，完全取决于它的 chat template（不同模型、甚至同系列不同打包都可能不一样）。模板不读这个变量时，传什么值都不会报错但也确实不生效；模板读取且做值域校验时，传一个值域外的值会在启动前被面板挡下（返回 422 并说明允许哪些值），避免容器起来后才在推理请求里炸出一个读不懂的错误。

**怎么办**：改成该模型模板支持的值，或者改回「继承模板默认」（`inherit`）。字段位置见[模型配置](./models.md)；每次请求级别的思考强度改写（区别于这里的模型固定配置）见[推理接口](./inference.md)。

## 怎么收集诊断信息

排查问题时，这几个入口能拿到最多信息：

- **日志页容器日志**（`/logs`，容器日志组）：`llama.cpp` 容器的实时日志流，模型加载失败、参数错误的具体报错都在这里。
- **环境自检**（设置页 → 运行环境）：六项固定检查，能快速定位是环境问题（Docker、路径、GPU、磁盘）还是配置问题。
- **面板自身容器日志**：`docker logs llamapad`（容器名以实际部署为准），面板自身的报错（而非模型容器的报错）看这里。
