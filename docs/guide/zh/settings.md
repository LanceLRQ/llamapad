# 设置项详解

设置页（`/settings`）是二级栏四组固定分组，不是一堆平铺的卡片：

| 组 | 名称 | 包含卡片 |
| --- | --- | --- |
| 01 | 运行环境 | 环境自检、运行镜像 |
| 02 | 模型库 | 命名空间、参数预设、下载源（Hugging Face） |
| 03 | 监控与通知 | 网络监控网卡、Webhook 通知 |
| 04 | 账号与数据 | 账号与安全、导入与备份 |

每组只在被选中时才取数（较重的两处是账号组的文件树扫描，以及监控组的网卡探测——它是这几组里唯一要读文件系统的异步取数），切组走 URL 上的 `?tab=` 参数，可以直接分享深链。

## 运行环境

### 环境自检（Doctor）

点「开始检查」触发一次性检测，六项固定顺序：

| 检查项 | 能查出什么 |
| --- | --- |
| Docker 连通 | 面板能否通过 `docker.sock` 列出容器 |
| models 目录 | 目录存在且面板运行身份对其可写 |
| 路径映射 | 模型库宿主机路径解析是否成功，以及来自哪一级（环境变量 / `panel.yaml` / 自动发现） |
| GPU | `nvidia-smi` 三态探测结果（可用 / 探测中 / 不可用，不可用在纯 CPU 部署下算正常，标为警告而非失败） |
| 下载源（Hugging Face） | 用当前生效的 Token / 镜像 / 代理配置实际尝试连通 |
| 磁盘空间 | models 根路径所在分区的剩余空间（低于 1GB 标失败，低于 5GB 标警告） |

六项检测互不牵连——某一项抛错只影响它自己的结果，不会让整页检测失败看不到其余五项的结论。这张卡排在第一位，是因为环境问题（Docker 连不上、目录没权限）通常是后续所有操作失败的根因，排在配置问题之前查更省时间。

### 当前启动镜像

新建与启动模型时的默认镜像；单个模型可以在编辑页的「镜像」字段单独覆盖。这里既能直接改镜像 tag（读数卡输入框保存），也能从官方镜像清单里选一个「设为启动镜像」，或在「自定义镜像」区块整体替换容器挂载点 / entrypoint / 启动参数 / 环境变量五个字段。

**改了之后何时生效**：写入立即落库，但**对已经在跑的容器不热更新**——面板检测到当前有模型正在运行时会弹出「需重启模型才生效」的提示，实际生效要等下一次启动（或重启）该模型。拉取镜像本身（把字节下载到本地）与"设为启动镜像"（改配置指向哪个 tag）是两件独立的事：拉取一个不相关的 tag 不会影响正在跑的模型。

**删除镜像有两条限制**：当前生效的那个镜像不允许删，要先把启动镜像切到别的 tag；被正在运行的容器占用的镜像由 Docker 自己拒绝，报错原样展示。

## 模型库

### 命名空间

管理模型的分组标签。语义上要留意：

- **新建**只登记这个分组，磁盘目录要等真正往里放文件时才会建；
- **重命名**只改该空间下模型配置的 `namespace` 字段，**不会移动任何磁盘文件**——磁盘目录重命名请去[文件管理](./files.md)；有运行中模型时会被拒绝；
- **删除**只删面板记录，磁盘上的目录与文件原样保留，可以在文件页另行清理；空间下还有模型记录时删除按钮会被禁用。

### 参数预设

一份不绑定任何模型的、有名字的参数覆盖列表，只写要带的那几个字段（与模型 `overrides.server` 同一套字段和值域）。套用是**快照语义**——选中时把值拷进目标模型的覆盖里，之后两者再无关系，改预设不会影响已经套用过它的模型，删预设也不影响已经套用出去的配置。

列表顶部固定是面板内置的「保守 / 平衡 / 全卸载」三档快速预设：只读，没有改名/删除入口，跟着代码版本走、不落库。下面是自己积累的预设，来源徽章有三种——手动（直接调 API 创建）、模型（在新建向导 / 编辑页 / 克隆页的参数表单里点「存为预设」）、README（在档案详情页的 README 视图里从某套推荐参数「存为预设」，这一类会额外标出来源仓库，点击可跳转回去）。这张卡上能做的只有改名与删除；套用与另存的入口都在别处——模型参数表单（见[模型管理](./models.md)）与 README 推荐卡、批量创建配置弹层（见[文件与命名空间](./files.md)）。

改名走 PATCH 接口，只改显示名；删除前会提示「删除不影响已经套用过它的模型配置」，确认后立即生效，不可撤销。预设名在同一份实例里唯一，重名会被拒绝。

### 下载源（Hugging Face）

三个独立的双源配置项：

**Token 双源**：环境变量 `HF_TOKEN` 优先于面板配置。env 存在时，面板里的 Token 输入框标记为"只读，环境变量优先生效"，此时保存/清除按钮不可用——要改用面板配置，得先去掉这个环境变量。面板**永不回显 Token 明文**，只显示来源徽标（环境变量 / 面板配置 / 未设置）与明文的**后 4 位**。

**镜像**：官方源 / `hf-mirror.com`（内置预设）/ 自定义 URL 三选一。

**出站代理双源**（同时作用于 Hugging Face 下载、Webhook 推送、下载器的所有出站请求）：面板配置覆盖 `panel.yaml` 的 `proxy` 字段，写入后**立即生效，不需要重启**。**清除面板配置会落回 `panel.yaml` 里的值，不是变成"无代理"**——`panel.yaml` 本身保持文件形态、不会被面板改写（面板起不来时仍可靠人工编辑这个文件诊断问题）。含用户名密码的代理地址在界面上展示时会遮蔽凭据部分（如 `http://***@host:port`），保存时的输入框也不会预填可能带凭据的旧值。

保存代理后建议点一次「测试连接」确认真的经代理连通，而不是只看保存成功的提示。

## 监控与通知

### 网络监控网卡

选择宿主机网络吞吐指标读取哪一块网卡，默认自动选择（通常会选中当前对外访问用的那一块）。这个选择只影响[概览页](./monitoring.md)的网络收发两项指标读哪块网卡，不影响其余任何功能；机器上探测不到物理网卡时会给出对应提示。

### Webhook 通知

把下载完成、模型启停等事件推送到 Bark / Telegram / 企业微信或自定义接收端（POST JSON）。渠道列表是**整表编辑**——新增/删除/改字段都只改本地草稿，点「保存」才会整体替换服务端配置；未保存时「测试推送」按钮禁用，因为测试请求按渠道 id 去服务端已保存的配置里查找，新增但未保存的行查不到。

订阅分组按事件前缀勾选（下载 / 模型启停 / 登录鉴权 / 命名空间 / 配置变更 / 文件操作 / 仓库档案），**全部不勾选代表订阅全部事件**，不是"什么都不推送"。

「测试推送」会用一条假事件立即发起一次真实出站请求，只回显 `{ok, status}`，**不会回显对方的响应体**——渠道 URL 是管理员自填的，回显响应体等于把面板变成一个通用的服务端出站探测器，这是刻意的安全限制。

## 账号与数据

### 账号与安全

- **API Token**：签发后明文**只显示一次**，之后列表里只保留后 4 位，供外部脚本经 `Authorization: Bearer lp_…` 调用面板 API（接口清单见[面板 API](./api.md)，推理中转的用法见[推理接口](./inference.md)）。吊销即时生效（删行）。
- **改密码**：需要验证旧密码；改密码**不会**吊销已经签发的 API Token（吊销走 Token 列表里独立的操作）。

### 导入与备份

- **导出全集**：把当前全部配置写成一份 YAML zip，路径与体积会在操作后回显。YAML 的字段结构见[配置格式与迁移](./config.md)。
- **自动快照**：开关打开后，每次配置变更都会自动把全量配置写入 `data/export/latest.yaml`——把这个目录纳入 git 仓库就是一份持续更新的配置备份，出问题时可以直接对比历史版本。
- **导入**：粘贴单份 YAML 文本，支持两种格式——`llamapad` 本产品导出格式（恢复全量配置）与 `bash`（`llama-launcher`）格式（导入单个模型到 `main` 空间）。同名冲突可选跳过 / 改名导入（依次试 `-1`、`-2`、`-3`……直到不与既有名或本批其他导入名冲突）/ 覆盖。导入前会先做一次预检：如果引用的模型文件（GGUF / mmproj）在本机磁盘上确实存在则直接导入；有缺失文件时会展示重指表格，让你为每一行手动选一个本机已有的替代文件，不选则跳过并保留原路径落库。
- **从 llama-launcher 迁移**：把 bash 版 `configs` 目录下的 `default.yaml` 与 `configs/models/*.yaml` 逐个粘贴添加为文件，一次性批量导入，模型统一落入 `main` 空间；bash 版独有的参数会以警告形式提示（不会导致导入失败）。逐项转换规则见[配置格式与迁移](./config.md)。
