# 文件与命名空间

## 目录结构

所有模型文件平铺在 `models/<命名空间>/` 下（命名空间可以是多级目录）。**命名空间是模型配置的分组标签，与文件实际所在的磁盘目录是两件互不隐含的事**。模型的 GGUF 路径是一段独立的相对路径字符串，跟它所属的命名空间字段没有绑定关系——同一份物理文件完全可以被不同命名空间下的多个模型配置引用（比如同一个 GGUF 被两个参数覆盖不同的模型共享）。

这样拆开是为了避免命名空间和物理文件绑得太死：改命名空间只改标签，不碰任何文件；要挪动物理文件位置，走的是文件页单独的移动操作。两件事分开做，不会互相牵连——重命名空间不会导致模型突然找不到文件，移动文件也不会意外影响命名空间归属。

## 命名空间

命名空间在「设置 → 模型库 → 命名空间」管理（模型页顶部也有一个「＋新建命名空间」快捷入口，顺手建一个就用）。新建只创建这条命名空间记录，磁盘目录要等真正用到时才会建，不会提前建好。

- **重命名**：只改这个空间的标签和其下模型配置的分组归属，不移动任何磁盘文件；该空间下有运行中的模型时会被拒绝
- **删除**：要求这个空间下没有任何模型配置（配置要先移走或删除），磁盘上的目录与文件不受影响，删除的只是这条命名空间记录，需要清理文件请到文件页操作。`main` 空间也允许删除，它只是导入时的默认落点：删掉之后如果再次导入或新建，面板会重新把它建出来，不用担心误删导致系统缺了什么必需的东西

命名空间与磁盘目录解耦，意味着文件页左侧看到的「文件夹」清单和模型页 / 设置页看到的「命名空间」清单，是两份口径不同的列表：一个是扫描磁盘得到的真实目录，一个是面板里配置好的命名空间分组。数量对不上是正常现象，不代表哪边算错了。

## 移动与改名时的引用检查

文件页对每个文件都会先扫描一遍「谁在引用它」——引用分两种：模型配置的路径字段与文件路径精确相等（哪怕文件已经不存在也算），或者配置写的是分片 glob、展开后命中这个具体文件。移动或改名一个被引用的文件时，面板会把所有引用它的模型配置（包括其他共享同一物理文件的模型，不只是你正在操作的这一个）一起重写指向新路径，不需要逐个模型手动改。

分片组按整组处理：选中任意一个分片会自动带出同组其余分片一起移动或改名，序号段（`-00001-of-00005` 这类）系统保留、不能手动编辑——分片模型的引用值是一份 glob，只搬一半分片会让 glob 在新位置只匹配到孤立的一片，模型会启动失败。

移动被引用的文件时，如果中途发生系统性故障，可能出现「文件已经搬到新位置，但引用它的配置还没跟着更新」这种中间状态。面板不会自动重试或回滚，而是提示你去模型页手动核对受影响的模型——这类失败通常源于确定性的校验错误，重试没有意义，需要手动处理。

## 删除的三层语义

删除在面板里被拆成互相独立的三层，各自的操作入口和影响范围都不一样：

| 层级 | 入口 | 影响 |
| --- | --- | --- |
| 删配置 | 模型编辑页「危险区」 | 只删这条模型的配置记录（含参数覆盖），GGUF 文件原样留在磁盘上 |
| 删文件 | 文件页 | 真正从磁盘删除物理文件；删除前会检查有没有模型配置在引用它 |
| 删命名空间 | 设置页 | 只删空间标签这条记录；要求该空间下已经没有任何模型配置 |

删文件时如果发现有配置在引用（且没有模型正在用这份文件运行），面板会先拒绝并列出引用清单，需要你确认「已了解删除后这些配置会失去文件引用（模型无法启动）」才会强制删除；如果引用它的模型正在运行，则无论如何都不允许删（不能让运行中容器脚下的文件被抽走），必须先停止该模型。

## 仓库档案

从 Hugging Face 仓库下载的文件由「仓库档案」统一管理（`models/repos`），每份档案对应磁盘上一个固定的目录，目录内藏着一个隐藏标记文件。这个标记文件是为了让搬走的目录还能被认回来：档案详情页本身只按登记的位置去看目录还在不在，搬走之后它会显示成「目录缺失」；要认回来，得重新走一次「新建同名档案」的流程，面板在探测阶段发现那个带标记文件的目录后会提示认领。

档案详情页列出仓库里的全部量化分组和各自的本地状态（未下载 / 部分分片 / 已下载 / 文件实际在别处），几个常用操作：

- **归位**：文件因为某种原因（比如手动挪动过）不在档案目录里时，把它挪回档案该在的位置
- **重新创建目录**：档案目录被手动删除或搬走、但登记信息还在时，重建这个目录
- **换存放位置**：把整个档案目录搬到别的位置，档案内全部文件跟着一起搬，涉及的模型配置引用同步重写
- **批量创建配置**：为已下载但还没有任何模型配置引用的量化，一次性按全局默认参数批量建好模型配置，建完再去模型页微调参数

档案目录由档案页整体管理，文件页里进入这类目录会看到提示——目录结构（新建文件夹、改名）不能在文件页直接编辑，也不能在文件页把档案目录内的单个文件改名（改名会让档案认不出这个文件，可能导致下次又重复下载一遍），这些操作要回到档案页进行。

删除档案有两种选择：只删登记信息（磁盘文件保留）或连同磁盘文件一起删除，删除界面会明确标出连带删除会清掉多大的文件、且不可恢复。两种情况会被拒绝：档案还有没跑完的下载任务时不能删；选了连同文件删除、而目录里的文件仍被某个模型配置引用时也不能删（不要求那个模型正在运行），要先把引用清掉。

## 磁盘占用

文件页左侧每个文件夹旁边都标着这个目录（含其下全部子目录）当前占用的空间与文件数；切到某个具体目录或「全部文件」，页头统计栏会显示当前切片的文件数、占用空间（GB）与其中被运行中模型占用的文件数。

「文件元信息」是独立于物理文件树的一张记录表（一行对应一个逻辑文件条目，分片组算一行），可以给文件手动标注量化标签和备注，也可以对文件发起后台哈希计算——计算的是文件的完整 sha256，可用于核实文件完整性或者辅助「自动寻找」功能重新链接一个被移走的文件。这张表登记的文件如果物理文件已经不在磁盘上了，会标成「孤儿记录」，可以用页面上的「清理孤儿记录」批量清掉，只影响这份元信息记录本身，不影响任何模型配置。
