# 术语表

面板界面与本套文档里反复出现的名词，按主题分组。每条给出的是够用的解释，展开说明在各自的链接里。

## 模型文件

**GGUF**
llama.cpp 使用的模型文件格式，扩展名 `.gguf`。一个文件里同时装着模型权重、元数据和对话模板，不需要额外的配置文件配套。面板只识别这种格式。

**量化**
把模型权重从高精度压到低精度，换取更小的体积和更低的显存占用，代价是输出质量有一定损失。文件名里的 `Q4_K_M`、`Q5_K_M`、`Q8_0` 就是量化档位：数字越小压得越狠、文件越小，`F16` / `BF16` 表示未量化。同一个模型仓库通常会同时提供多个档位供选择，选哪个取决于你的显存。参见[模型下载](./downloads.md)。

**分片**
体积过大的模型会被切成多个文件发布，文件名形如 `model-00001-of-00003.gguf`。这几个文件必须集齐、且放在同一个目录里才能启动。面板在下载、移动、改名时都按整组处理，选中其中一个会自动带出同组其余分片，不会让你只搬走一半。参见[文件与命名空间](./files.md)。

**mmproj**
多模态投影文件，让模型能够理解图片输入。它是主模型的配套文件，本身不能单独启动，需要在模型配置里与主模型一起指定。仓库里通常以 `mmproj` 命名。参见[模型管理](./models.md)。

**对话模板（chat template）**
决定多轮对话如何拼接成模型实际读到的文本，内嵌在 GGUF 文件里，不同模型各不相同。它同时决定了模型接受哪些参数——面板的思考强度中转映射就是依据模板内容判断该模型支不支持 `reasoning_effort`。参见[推理接口](./inference.md)。

## 面板概念

**命名空间**
模型配置的分组标签，用来把模型按用途或来源分类。它与文件实际所在的磁盘目录是两回事：改命名空间只改标签、不动任何文件，同一份 GGUF 也可以被不同命名空间里的多个模型配置同时引用。参见[文件与命名空间](./files.md)。

**仓库档案**
从 Hugging Face 下载时登记的一份记录，对应磁盘上一个固定目录，保存着该仓库的量化清单和每一项的本地下载状态。它的用处是让同一个仓库后续继续挑别的量化下载时，面板知道哪些已经有了。参见[文件与命名空间](./files.md)。

**模型配置**
面板里的一条模型记录，包含模型名、指向的 GGUF 文件，以及这个模型自己的推理参数。它和磁盘上的文件是两回事——删除模型配置不会删文件。参见[模型管理](./models.md)。

**参数覆盖与生效参数**
每个模型的推理参数 = 全局默认配置叠加该模型自己的覆盖项。覆盖只记录与默认值不同的那部分，其余跟随默认值变化。两者合并后的结果叫「生效参数」，也就是启动时真正拼进命令行的那一份，编辑页有预览。参见[模型管理](./models.md)。

**宿主机视角的路径**
面板配置里的绝对路径（模型库位置、挂载映射这些）按宿主机的目录结构书写，不是按面板容器内部看到的路径——启动模型容器时要把目录挂载进去，而挂载只认宿主机路径。模型自己的 GGUF 路径是另一回事，那是相对模型库根目录的相对路径。参见[部署与运维](./deployment.md)。

## 运行与资源

**就绪**
容器起来了，不等于模型可以接受请求——权重加载需要时间，大模型上这个过程可能要几十秒。面板会持续探测直到服务真正开始响应，这之后才算就绪。启动窗口期内发起的推理请求会拿到 502。参见[推理接口](./inference.md)。

**显存（VRAM）**
显卡上的内存，模型权重和上下文缓存都占用它。显存不足是启动失败最常见的原因。面板会对照这个模型过去的运行记录给出提示，但不会拦截启动——影响显存占用的因素太多，给不出精确预测。参见[排错](./troubleshooting.md)。

**上下文长度**
模型单次能处理的最大 token 数，包含对话历史和本次输出。调大它能记住更长的对话，同时显著增加显存占用。参见[模型管理](./models.md)。

**KV Cache**
推理过程中缓存的中间结果，用来避免重复计算已经生成过的内容。它随对话变长而增长，是上下文长度直接影响显存占用的原因。监控页可以看到它的实时用量。参见[监控与日志](./monitoring.md)。

**槽位（slot）**
llama-server 用来并行处理请求的位置，数量决定了能同时服务多少个对话。槽位占满时后来的请求排队等待。监控页的「活跃槽位」显示的就是当前占用数。参见[监控与日志](./monitoring.md)。
