# 模型管理

## 多模型运行

面板可以同时运行多个模型。启动一个模型不会停掉其他正在运行的模型；对已经在运行的模型再点一次「启动」会重建它的容器。显存够不够由你判断，启动前的显存预警见下文；真装不下时 llama.cpp 会自己报错，启动进度框会显示失败原因。

### 端口与容器名

每个运行中的模型各占一个宿主机端口和一个容器名。取值优先用模型自己的覆盖配置，没有覆盖就用默认配置（`host_port: 18080`、`container_name: llama-server`）。启动时如果端口已经被别的运行中模型或宿主机上的其他程序占用，面板自动顺延到下一个空闲端口；容器名与运行中的其他模型重名时，自动在后面追加 `-<模型名>`。

因此同时运行多个模型时，后启动的那个端口可能和配置里写的不一样。实际端口以模型首页「正在运行」区和模型列表里显示的为准，两处都提供「打开 llama UI」和「复制地址」入口。需要固定端口的模型（比如 nginx 反代或客户端直连），单独给它配一个不与其他模型重复的端口。编辑模型配置时，如果端口与别的模型相同，表单会给出提示，但不拦截保存。

### 默认模型

API 中转请求里不带 `model` 字段时发往默认模型；Chat 页和日志页打开时也先选中它，有多个模型在运行时可以在页头切换。启动第一个模型时它自动成为默认模型；有多个模型在运行时，可以在模型首页「正在运行」区的运行卡上点「设为默认」切换。

默认模型只记在面板进程里，不写数据库。默认模型被停止或异常退出时，自动换成最早启动的在跑模型；全部停止后没有默认模型。面板重启后同样按「最早启动」重新选。重启默认模型不会改变默认。

### 启停互斥与运行中限制

同一个模型的启停请求互斥：上一个请求还没跑完时，针对同一模型的第二个请求会被直接拒绝（HTTP 409），而不是排队等待。排队会让一连串点击在后台依次生效，结果难以预期；直接拒绝、稍后重试更清楚。不同模型之间的启停互不影响，可以同时进行。

运行中的模型有额外限制：禁止删除配置、禁止改命名空间、禁止移动物理文件，这几种都返回 409。还有一种情况是 423：你要移动的文件被**另一个**正在运行的模型共享，锁在别人手里，先停掉那个模型才能动。共同的前提是：正在被容器使用的东西，不能在使用期间被改动。

## 状态与就绪判定

模型列表的状态徽标：

| 状态 | 含义 |
| --- | --- |
| 运行中 | 该模型的容器正在跑，即便面板本身重启过，也能重新识别出这个状态 |
| 就绪 | 未运行，且 GGUF 与（如果配置了）mmproj 文件都在磁盘上找得到 |
| 缺文件 | GGUF 主文件缺失，无法启动 |
| 缺 mmproj | GGUF 在，但配置的 mmproj 投影文件缺失 |

**列表里的「运行中」只代表容器在跑，不等于 llama-server 已经监听端口、能处理推理请求**，详见[快速开始](./quickstart.md)。真正的就绪探测只在启动进度框和 Chat 页里用到，用来决定要不要显示加载态；列表页的「运行中」徽标不会因为还没就绪而有变化。

如果模型正在运行，而你在这之后又保存过一次配置，列表和编辑页会出现「配置已变更」提示：说明运行中的容器仍然用的是启动时的旧参数，新参数要等重启这个模型才会生效，保存配置本身不会热更新正在运行的容器。

## 启动前的显存预警

点「启动」弹出的进度框，会先拉一次该模型的历史运行数据，如果**当前空闲显存 < 该模型过去运行时观察到的显存净增量峰值**，顶部会出一条琥珀色提示。这只是提示，不拦截：显存占用受量化、上下文长度、KV cache 类型等多个因素影响，面板给不出精确预测，硬拦截只会挡住本来能跑的合法操作；真装不下时 llama.cpp 自己会报错，启动失败的提示流程照样接得住。没有历史运行记录，或者取不到 GPU 读数（没装 NVIDIA Container Toolkit）时，不显示任何预警。

其他模型正在运行时，「当前空闲显存」已经扣掉了它们的占用。与其他模型运行时间有重叠的那几次运行不计入历史峰值：那段时间的整卡显存读数里混着别的模型，算进去会把峰值抬高。

## 配置编辑：默认值与覆盖的合并

每个模型的实际生效参数 = 全局默认配置（设置页维护）叠加该模型自己的参数覆盖，参数覆盖只存与默认值不同的那部分差异，未覆盖的字段跟随默认值。改一次全局默认（比如统一调整批大小），所有没有单独覆盖过这一项的模型都会跟着变，不用逐个改。编辑页的「生效参数预览」展示的就是合并后的最终值，也就是启动时真正会拼进 llama-server 命令行的那一份。

配置分四节：基本信息（显示名 / 命名空间 / GGUF 与 mmproj 路径）、Docker（容器名 / 端口 / 镜像 / GPU）、性能参数（上下文长度、GPU 层数、K/V Cache 类型等）、采样参数（温度、Top-p、Top-k 等）。命名空间只是配置分组标签，与文件实际所在的磁盘目录无关，改命名空间不会移动任何文件；GGUF 路径支持分片 glob：通配符替换掉整段序号尾缀，而不是写死某一片（如 `main/Qwen3-30B-Q4_K_M-*.gguf`），可以跨命名空间引用同一份物理文件。

性能参数与采样参数两节都带一个预设选择器（内置三档快速预设 + 自己保存过的参数预设），套用只补丁式覆盖预设里写了的那几个字段，其余保持原样；也可以把当前填的值另存成一条新预设，供以后新建或编辑其他模型时复用。这个选择器在编辑页、克隆页与新建向导第二步是同一份组件，行为一致。

删除模型配置只删这个模型的配置记录（含全部参数覆盖），GGUF 文件本身留在磁盘上不受影响。这是三层删除语义（配置 / 文件 / 命名空间）里最外层的一层，另外两层的边界见[文件与命名空间](./files.md)。

## 思考强度（reasoning effort）

这是较新的配置项，取值口径与常见认知不太一样：

**允许的取值因模型而异：面板每次从这份 GGUF 内嵌的 chat template 里读取实际支持的档位，不是按模型名查一张写死的表。** 同系列模型不同打包方允许的取值范围可能不同，比如某个魔改版模板会把 `high` 额外映射到 `xhigh`，另一个版本没有这层映射。面板会检测模板里有没有 `reasoning_effort` / `reasoning_strength` 这两个变量名，检测到了才认为该模型支持这个特性，并尝试从模板里解析出具体允许哪些档位（`minimal` / `low` / `medium` / `high` / `xhigh` / `max`）；解析不出来时会展示全部枚举，需要你自行判断哪些真正可用。

选择器里的「跟随模板自身默认」（值为 `inherit`）永远可选，且不会作为参数下发给 llama.cpp，选这个就是把决定权完全交给模板自己的默认逻辑。

三种边界情况要留意：

- **模板本来不认这个变量**：传任何值都会被静默忽略，容器照常启动、健康检查照常通过，配了跟没配一样。llama.cpp 只处理模板里真正写了要读的变量
- **模板认这个变量但校验值域**：如果传了一个不在模板允许范围内的值，容器依然能正常启动、健康检查依然正常，**只有真正发起一次带这个参数的推理请求时才会报错，返回 HTTP 500**（错误信息来自模板校验，样子类似 jinja 报错）。在编辑页保存配置时、以及每次启动前，面板会做前置校验，用模板实际允许的值域拦截明显超出范围的取值（新建向导与克隆时模型还没落库、读不到模板，这一步不做，非法值要等到之后编辑保存或启动时才会被拦下）；但如果面板判断不出该模型是否支持这个特性（模板没内嵌，或者支持但解析不出具体档位），不会强行拦截，只会给出提示
- **「思考模式」关闭时**，思考强度选择器会被禁用：这个参数依赖「是否启用思考」这层开关，思考关掉后配了也不会生效

## 克隆与新建向导的区别

「另存为新模板」（列表行 ⋯ 菜单）把源模型的全部配置预填进一张新建表单，提交前不落库，可以随意改参数或改文件后再创建；不受源模型运行状态影响（克隆只建一条新的配置记录，不碰任何容器或磁盘文件），运行中的模型也能克隆。

新建向导（`models/new`）分两步：第一步从磁盘已有文件或刚下载好的文件里选文件，第二步填基本信息与参数。两者的差别在于起点：克隆从一个已存在的配置出发（预填好全部参数），新建向导从一个文件出发，参数可以从零填，也可以套一份预设。面板内置「保守 / 平衡 / 全卸载」三档快速预设，加上自己保存过的参数预设（管理入口见[设置项详解](./settings.md)），套上之后仍可继续手动微调。

## HuggingFace 发现区

模型首页在「正在运行」和最近更新的仓库两区之下还有第三区：HuggingFace 发现区。默认列出 HuggingFace 上当下最热门的 GGUF 仓库，口径与 HF 站内的 Trending 榜一致，并固定只看带 `gguf` 标签的仓库——面板只跑 llama.cpp，列出别的格式是给你挖坑。

区头的搜索框在停止输入约 0.4 秒后就地搜索，清空即回热门榜。搜索词不写进地址栏：这块是首页的一个探索入口，不是可分享可回退的独立页面，浏览器「后退」仍然应该是离开首页，而不是在首页内部翻搜索历史。

每张卡片给出热度、点赞数、下载量、任务类型与最近更新时间，两个出口：「下载」把这个仓库预填进新建下载弹层并自动探测一次量化分组，右侧的箭头按钮在 HuggingFace 原站打开这个仓库。已经建过仓库档案的仓库会标上「已有档案」徽标，主按钮也换成「查看档案」直达详情页——热门榜里撞上自己已有的仓库是常事，这个徽标是为了不让你重复建档。结果满一屏时网格下方会出现一条通栏按钮把你送去 HF 站内的列表页；面板自己不做翻页，也不做按作者、参数量、量化类型的分面筛选，原站的筛选器完整得多。

所有外链跟随设置页里生效的镜像端点：配了 `hf-mirror.com` 就往镜像站开，没配才走官方站。

热门榜缓存 **30 分钟**（可用环境变量 `PANEL_HF_TRENDING_TTL_MINUTES` 覆盖，设为 `0` 表示永不自动过期、只能靠手动刷新），区头的刷新按钮绕过缓存强制重取。这份缓存只在面板进程内存里，不落数据库，所以面板重启后榜单要重新拉一次。取数失败时，如果缓存里还留着上一批数据，会照常显示旧卡片，并在网格上方提示这是多久之前的缓存以及这次失败的原因；连旧数据都没有时才整块显示错误和「重试」。搜索结果不缓存。
