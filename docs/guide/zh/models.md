# 模型管理

## 单模型约束

面板同一时刻只运行一个模型。一张显卡的显存是独占资源，同时跑两个大模型大概率两个都装不下。启动一个新模型时，面板会先停掉当前运行的模型、再启动目标模型；列表页把这个动作叫做「切换」，你不需要自己先手动停再手动启，点一次就够。

启停请求之间还加了互斥：上一个启停请求还没跑完时，第二个请求会被直接拒绝（HTTP 409），而不是排队等待。排队会让最终跑起来的是哪一个模型变得难以预期；直接拒绝、失败后重试一次更清楚。

模型「配置运行中」也有额外限制：运行中的模型禁止删除配置（409）、禁止改命名空间或移动物理文件（同为 409，共享该文件的其他运行中模型同样会挡）。共同的前提是：正在被容器使用的东西，不能在使用期间被改动。

## 状态与就绪判定

模型列表的状态徽标：

| 状态 | 含义 |
| --- | --- |
| 运行中 | 该模型的容器正在跑，即便面板本身重启过，也能重新识别出这个状态 |
| 就绪 | 未运行，且 GGUF 与（如果配置了）mmproj 文件都在磁盘上找得到 |
| 缺文件 | GGUF 主文件缺失，无法启动 |
| 缺 mmproj | GGUF 在，但配置的 mmproj 投影文件缺失 |

**列表里的「运行中」只代表容器在跑，不等于 llama-server 已经监听端口、能处理推理请求**，详见[快速开始](./quickstart.md)。真正的就绪探测只在启动进度框和 Chat 页里用到，用来决定要不要显示加载态；列表页的「运行中」徽标不会因为还没就绪而有变化。

如果模型正在运行，而你在这之后又保存过一次配置，列表和编辑页会出现「配置已变更」提示：说明运行中的容器仍然用的是启动时的旧参数，新参数要等重启这个模型才会生效——保存配置本身不会热更新正在运行的容器。

## 启动前的显存预警

点「启动」或「切换」弹出的进度框，会先拉一次该模型的历史运行数据，如果**当前空闲显存 < 该模型过去运行时观察到的显存净增量峰值**，顶部会出一条琥珀色提示。这只是提示，不拦截——显存占用受量化、上下文长度、KV cache 类型等多个因素影响，面板给不出精确预测，硬拦截只会挡住本来能跑的合法操作；真装不下时 llama.cpp 自己会报错，启动失败的提示流程照样接得住。没有历史运行记录，或者取不到 GPU 读数（没装 NVIDIA Container Toolkit）时，不显示任何预警。

## 配置编辑：默认值与覆盖的合并

每个模型的实际生效参数 = 全局默认配置（设置页维护）叠加该模型自己的参数覆盖，参数覆盖只存与默认值不同的那部分差异，未覆盖的字段跟随默认值。改一次全局默认（比如统一调整批大小），所有没有单独覆盖过这一项的模型都会跟着变，不用逐个改。编辑页的「生效参数预览」展示的就是合并后的最终值，也就是启动时真正会拼进 llama-server 命令行的那一份。

配置分四节：基本信息（显示名 / 命名空间 / GGUF 与 mmproj 路径）、Docker（容器名 / 端口 / 镜像 / GPU）、性能参数（上下文长度、GPU 层数、K/V Cache 类型等）、采样参数（温度、Top-p、Top-k 等）。命名空间只是配置分组标签，与文件实际所在的磁盘目录无关，改命名空间不会移动任何文件；GGUF 路径支持分片 glob（如 `main/Qwen-*-00001-of-00002.gguf`），可以跨命名空间引用同一份物理文件。

删除模型配置只删这个模型的配置记录（含全部参数覆盖），GGUF 文件本身留在磁盘上不受影响。这是三层删除语义（配置 / 文件 / 命名空间）里最外层的一层，另外两层的边界见[文件与命名空间](./files.md)。

## 思考强度（reasoning effort）

这是较新的配置项，取值口径与常见认知不太一样，值得单独说清楚：

**允许的取值因模型而异：面板每次从这份 GGUF 内嵌的 chat template 里读取实际支持的档位，不是按模型名查一张写死的表。** 同系列模型不同打包方允许的取值范围可能不同——比如某个魔改版模板会把 `high` 额外映射到 `xhigh`，另一个版本没有这层映射。面板会检测模板里有没有 `reasoning_effort` / `reasoning_strength` 这两个变量名，检测到了才认为该模型支持这个特性，并尝试从模板里解析出具体允许哪些档位（`minimal` / `low` / `medium` / `high` / `xhigh` / `max`）；解析不出来时会展示全部枚举，需要你自行判断哪些真正可用。

选择器里的「跟随模板自身默认」（值为 `inherit`）永远可选，且不会作为参数下发给 llama.cpp——选这个就是把决定权完全交给模板自己的默认逻辑。

三种边界情况要留意：

- **模板本来不认这个变量**：传任何值都会被静默忽略，容器照常启动、健康检查照常通过，配了跟没配一样。llama.cpp 只处理模板里真正写了要读的变量
- **模板认这个变量但校验值域**：如果传了一个不在模板允许范围内的值，容器依然能正常启动、健康检查依然正常，**只有真正发起一次带这个参数的推理请求时才会报错，返回 HTTP 500**（错误信息来自模板校验，样子类似 jinja 报错）。面板在保存配置和每次启动前都会做前置校验，用模板实际允许的值域拦截明显超出范围的取值；但如果面板判断不出该模型是否支持这个特性（模板没内嵌，或者支持但解析不出具体档位），不会强行拦截，只会给出提示
- **「思考模式」关闭时**，思考强度选择器会被禁用：这个参数依赖「是否启用思考」这层开关，思考关掉后配了也不会生效

## 克隆与新建向导的区别

「另存为新模板」（列表行 ⋯ 菜单）把源模型的全部配置预填进一张新建表单，提交前不落库，可以随意改参数或改文件后再创建；不受源模型运行状态影响（克隆只建一条新的配置记录，不碰任何容器或磁盘文件），运行中的模型也能克隆。

新建向导（`models/new`）分两步：第一步从磁盘已有文件或刚下载好的文件里选文件，第二步填基本信息与参数。两者的差别在于起点——克隆从一个已存在的配置出发（预填好全部参数），新建向导从一个文件出发（参数从零填，或用面板提供的三档快速预设）。
